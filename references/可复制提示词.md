# 通用项目关系分析提示词

把下方整段复制到能读取仓库文件的代码助手中，替换方括号内容。无需依赖本技能；若当前工具安装了 `repo-atlas`，也可直接使用文末的简短调用。

```text
请基于当前仓库的真实源码，为我生成一份可直接离线打开的交互式 HTML 项目分析文档，帮助我理解复杂项目的模块构成、业务链路、数据关系和外部依赖。

项目路径：[项目根目录；多个相关仓库可列出]
分析范围：[整个项目 / 指定模块与其必要上下游]
读者：[接手研发人员 / 架构师 / 产品业务人员]
输出位置：[工作区内目录]
重点关注：[可选，例如订单与库存、权限、异步任务、历史兼容]

执行方式：
1. 先读取当前目录适用的 AGENTS.md、CLAUDE.md、README、项目记忆和交接文档，简要说明约束。记录实际分支、提交与工作区变化。没有可读记忆就明确说明。
2. 阅读入口、路由、核心服务、数据访问、模型、迁移、配置和关键测试。先确认事实再得出结论，不凭类名、字段名、目录或早期需求猜实现。
3. 先建立与范围相称的覆盖账本，按项目实际选择入口与角色、认证授权、主业务链、状态与数据、异步任务、外部副作用、失败恢复、一致性与并发、配置、部署运行、可观测性和测试等维度，标明已覆盖、部分覆盖、待确认或不适用。
4. 从实际用户动作或事件追踪完整链路：入口、权限与校验、业务编排、数据读写、状态变化、外部副作用、下游读取以及失败/重试/补偿。将关键结论绑定到真实文件、行号和少量可读摘录。
5. 区分业务模块与部署单元、当前事实与历史快照、审批/执行计划与实际结果、主链与兼容路径、配置值与线上有效值、已实现能力与规划。无法确认时标注推断或待确认，不擅自补齐常见模块。

内容与图表：
- 首屏给可读的模块关系总览，再提供模块构成树及有助于理解的子图。
- 根据项目实际需要选择流程、时序、状态、逻辑数据关系和外部依赖图，不固定图表数。
- 每张图只表达一种主关系；节点用清晰业务语言，边写明动作或数据含义。长类名、字段和源码放到可展开说明。
- 状态机读取实际枚举与迁移逻辑；多个状态机分开。ER 图关联字段和基数需要代码或约束依据，不默认存在物理外键。非关系型项目用文件、集合、键和消息关系表达。
- 明确当前边界、历史兼容和规划关系；项目没有规划资料就省略规划视图。
- 将影响理解、变更或运行判断的事实、决策、风险和缺口整理成“发现项”，区分已确认、推断和待验证，并给出影响与最短验证路径。不要把普通代码观察堆成风险清单。
- 建立可搜索的发现项、覆盖矩阵、模块、相关数据对象、接口/事件、配置和源码索引。计数从当前扫描计算，表名引用数不等于线上表数。
- 每个关键模块说明职责、上下游和核心数据，附源码位置及内嵌摘录，使离开仓库目录也能阅读依据。

HTML 体验：
- 使用 Mermaid 固定版本渲染，优先将库、样式、数据和逻辑全部嵌入单个 HTML；双击即可离线打开，不依赖项目应用和 CDN。
- 采用简洁的浅色背景、低饱和分类色、左侧目录和宽幅画布。先讲清关系，再展示细节。
- 第一屏同时呈现项目定位、当前视图、分析基线、证据规模和核心关系，不做营销封面。
- 支持图表切换、跨视图/模块/发现项/对象/配置的全文搜索、节点说明、视图级源码依据、缩放、拖动、适应画布、全屏，以及 SVG / Mermaid 源码导出。
- 手机端把数据索引转换为带字段名的纵向记录，不依赖横向滚动阅读关键结论。
- 长图保持文字可读，手机使用纵向简图或合适的缩放与浏览方式，不将一整张大图缩成无法辨认的缩略图。
- 保留生成源或结构化清单，便于后续随代码更新。避免把密钥、凭据、个人数据或整个环境文件嵌入报告。

验证与交付：
- 检查每张 Mermaid 图实际渲染成功、没有页面错误、文件与证据锚点存在，图/表/正文与源码一致。
- 使用可用浏览器在断网模式下验证全文搜索、发现项和覆盖矩阵、节点与视图证据、缩放拖动、导航和导出；检查桌面、320px 手机以及最复杂图的截图。
- 缺少浏览器或外部环境时明确写出未验证项，不声称测试通过。文档任务不要求启动整套业务系统。
- 交付 HTML 路径、可维护的生成源、覆盖范围和实际验证结果。直接完成已授权的分析和文档工作；只有真正缺少必要信息时才提问。
- 首次分析后保存本地快照；后续优先用快照、文件哈希、Git diff 和证据反向索引计算增量，只把受影响模块和失效证据交给模型复核。使用 `snapshot.mjs`、`delta.mjs`、`refresh.mjs` 生成候选更新，不要每次把整个仓库重新读入上下文。
- 增量刷新不得静默覆盖基线：输出变更摘要、受影响对象、失效证据、全量重分析建议和待审核的 `atlas.next.json`。
- 优先检查 `reusedEvidence`、`recomputedEvidence`、`staleEvidence` 与 `manifestChanged`；删除文件或清单变化时，不把旧结论当作新事实。需要保存当前快照时显式传 `--snapshot-output`，不要覆盖基线快照。
- 不修改业务代码、不执行数据库变更、不操作生产环境；长期记忆仅在明确授权后写入。
```

已安装技能时可直接使用：

```text
使用 $repo-atlas 分析 [项目路径] 的 [整个项目 / 模块范围]，
面向 [读者] 生成可离线打开的 HTML 项目图谱，输出到 [目录]。
重点关注 [可选关注点]，保留模块总览、必要子图、覆盖矩阵、关键发现、源码依据和交互导出。
```
